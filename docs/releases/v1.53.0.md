# v1.53.0 — OpenClaw test audit

Выпуск добавляет самостоятельный **openclaw-test-audit@1.0.0**, адаптацию
[OpenClaw test-audit](https://github.com/openclaw/openclaw/blob/70bfdc2b58e42f02af5bdc4d345875a9e6ad3928/.agents/skills/test-audit/SKILL.md)
для Pri-Fly. Пакет проверяет качество изменённых тестов и возвращает отчёт,
связанный с состоянием кода. При пустой выборке AI-сессия не запускается.

Требования: **Pri-Fly ≥0.13.77**, Python 3 stdlib и выбранный coding host.
AI Factory и установленный OpenClaw skill не требуются. Checklist встроен
с закреплённым upstream commit, source hashes и MIT license. Это наша адаптация;
vendor prefix отражает источник критериев.

Семь прежних пакетов сохраняют bytes и версии относительно v1.52.0. Новый
workflow автоматически в них не включается. Разработчики могут самостоятельно
собрать [opt-in маршрут через extend.yaml](../../examples/test-audit-extension/README.md).
На 0.13.77 extend вставляет шаг с одним typed input; полноценный nested workflow
import не обещается. Будущая W6/E5 работа этим выпуском не реализуется.

## Установка

В инициализированном проекте:

```sh
prifly project workflows search openclaw-test-audit
prifly project workflows add openclaw-test-audit --repository .
prifly project local set --repository . \
  --allow-executable python=/absolute/path/to/python3
```

Прямая установка из tag:

```sh
prifly project workflows add StenHigh/prifly-aif-workflows \
  --path openclaw-test-audit --ref v1.53.0 --repository .
```

Каталог закрепляет `ref: v1.53.0` и полный source commit. Search/add не дают
доверие для запуска программ. Настройка config, reviewed start и continue —
в [README пакета](../../openclaw-test-audit/README.md).

Проект задаёт исходный base commit и свои test patterns. Программа учитывает
committed/worktree/index/nonignored untracked изменения, включая новые тесты
в существующих файлах, удаления и переименования. В отдельном новом checkout
Run движок требует чистое дерево; незакоммиченные результаты текущего Run
проверяются композицией внутри него, с сохранением native ownership.

## Результат и границы

- `passed`/`skipped` → succeeded; конкретные дефекты `failed` → partial.
- Недоступные обязательные данные, неполный или устаревший отчёт → blocked/partial.
- Invalid preparation → rejected. Пакет не исправляет код, не удаляет тесты
  и не делает commit/push. Continue повторяет весь quality на сохранённом дереве.

Машина проверяет полноту отчётных **путей** и Git freshness. Полезность тестов
оценивает reviewer; динамический pre-fix/post-fix proof сам по себе не создаётся.
Detection зависит от patterns проекта, отдельная модель не аттестуется.
Native qualification использует синтетический reader, реальные CLI/программы/Git.
