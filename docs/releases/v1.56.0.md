# v1.56.0 — verify fail/no_work завершается rejected

Статус: подготовлен к публикации; tag и центральный каталог ещё не обновлены.
Основание: согласованный контракт [issue #7](https://github.com/StenHigh/prifly-aif-workflows/issues/7).

| Пакет | Прежняя версия | Новая версия |
|---|---|---|

| aif-profiled | 1.49.0 | 1.50.0 |

Остальные шесть пакетов сохраняют bytes и версии v1.55.0.
Минимальная версия Pri-Fly остаётся0.13.64; проверка использует official0.13.82.

Verify fail/no_work без gate больше не должен давать unhandled_child_outcome.
Корень завершает Run как completed/rejected без root outputs.
Это правило включает fail/no_work вложенного fix. Прежний gate остаётся в истории.
Partial с gate и явное выключение verify сохраняют действующие маршруты.

```text
fail/no_work -> дочерний no_work -> completed/rejected
                                      -> reviewed continue -> verify целиком
```

Continue сохраняет warmup/plan/improve/implement, план и текущее рабочее дерево.
Он повторяет корневой verify с новым счётом раундов.

## Установка после публикации

Выполните команду только для нужного пакета:

```sh
prifly project workflows add StenHigh/prifly-aif-workflows --path aif-classic --ref v1.56.0 --repository .
prifly project workflows add StenHigh/prifly-aif-workflows --path aif-profiled --ref v1.56.0 --repository .
```

Для уже установленного пакета:

```sh
prifly project workflows update aif-classic --ref v1.56.0 --repository .
prifly project workflows update aif-profiled --ref v1.56.0 --repository .
```

Готовый task и полные prepare/start/continue: [пример](../../examples/classic/README.md).
Opt-in расширения review/UI/UX: отдельный [W6 recipe](../../examples/review-uiux-extensions/README.md).
Самостоятельная установка не создаёт дополнительных import или repair маршрутов.
Catalog entries этого PR подготовлены для v1.56.0; default catalog обновляется при публикации.

## Старые Runs

Завершите остановленные Runs до обновления, если это возможно.
Новый переход verify меняет форму стадии; continue от старого Run может вернуть recover_frontier_changed.
Прежние failed Runs с unhandled_child_outcome уже отклоняют continue с recover_frontier_unsupported на0.13.82.
Обновление пакета не переписывает их историю и не обещает миграцию.
Сохраните рабочее дерево и передайте его владельцу для отдельного осмотра.
