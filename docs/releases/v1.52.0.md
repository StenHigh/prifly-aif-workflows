# v1.52.0 — небольшие фичи и проверяемая приёмка

Выпуск добавляет три самостоятельных workflow и проектный пример приёмки перед
интеграцией. Содержимое `aif-classic`, `aif-profiled`, `aif-fanout` и `aif-fix`
не изменено относительно v1.51.2; прежние записи этих пакетов в каталоге сохранены.

| Что | Версия | Для чего |
| --- | --- | --- |
| `aif-review-evidence` | 1.0.0 | Проверить готовый код по явному списку требований, сохранить отчёт с привязкой к candidate. |
| `aif-ui-ux` | 1.0.0 | Проверить экраны и пользовательские сценарии в среде проекта, сохранить UI/UX-отчёты и освободить свои ресурсы. |
| `aif-feature` | 1.2.3 | Реализовать одну ограниченную фичу и повторять полную приёмку после исправлений до локального commit. |
| `examples/verified-integration` | 1.0.0, проектный пример | Проверить точный объединённый код перед отдельно разрешённой интеграцией. Это не запись каталога. |

Для первых двух пакетов требуется Pri-Fly ≥0.13.76, для feature — ≥0.13.77.
Обязательные ворота выпуска проверены на официальном **Pri-Fly v0.13.77**.
Python 3 и AI Factory skills устанавливает проект; квалификация skills — 2.19.0.
Установка workflow не предоставляет доверие к пакету и не устанавливает зависимости.

## Установка и обновление

Из корня инициализированного проекта:

```sh
prifly project workflows search feature
prifly project workflows add aif-feature --repository .
# При необходимости самостоятельной приёмки:
prifly project workflows add aif-review-evidence --repository .
prifly project workflows add aif-ui-ux --repository .
```

Каталог закрепляет `ref: v1.52.0` и полный source commit. Для прямой установки:

```sh
prifly project workflows add StenHigh/prifly-aif-workflows \
  --path aif-feature --ref v1.52.0 --repository .
```

Если пакет уже установлен из пилотной версии, сначала завершите активные Runs
проверенным старым helper. Затем обновите нужный пакет:

```sh
prifly project workflows update aif-feature --ref v1.52.0 --repository .
```

Аналогично обновляются `aif-review-evidence` и `aif-ui-ux`. Локальные правки
upstream-файлов могут остановить update; сохраните их и разберите отличие.
Проектные `extend.yaml` и overlay сохраняются. Одинаковая версия сама по себе
не гарантирует совместимость старых accepted prefixes: просмотрите
`project continue --prepare`, если продолжаете остановленный Run.

README внутри пакетов сохраняют проверенные байты квалификационного checkpoint,
включая инструкции ручной пилотной установки. Актуальные release-команды — здесь
и в [общем README](../../README.md); перепаковывания `aif-feature@1.2.3` нет.

## Выбор ревью и примеры

По умолчанию `aif-feature` выполняет приёмку последовательно. Backend обходит
браузерные этапы; frontend требует обязательные UI- и UX-сценарии и явный
[контракт среды](../product-review-environment.md).

- [Небольшая фича](../../examples/small-feature/README.md): task JSON, backend,
  frontend и настройки трёх режимов, команды preview и reviewed start.
- `parallel-backend`: отдельные Codex CLI сессии security/code review;
  [подключение host adapter](../../aif-feature/README.md#опциональное-параллельное-backend-ревью).
- `parallel-ui-ux`: отдельные CLI-сессии, browser contexts и identities;
  [настройка и протокол project adapter](../parallel-ui-ux.md).
- [Приёмка интеграции](../../examples/verified-integration/README.md): отчёт по
  объединённому коду; локальное объединение и Draft MR выбираются отдельно.

Параллельный режим требует явного подключения проверенного helper к runner.
Установка из каталога его автоматически не включает. Для UI/UX квалифицированы
**1–3 полных круга**,4–8 отклоняются до writers; sequential/backend сохраняют1–8.
Нужен owned isolated HTTP loopback adapter с отдельными contexts/identities и
ресурсом ёмкостью минимум2. Общий стенд с лимитом1 остаётся последовательным.
Нет молчаливого fallback в sequential или code-only. Cleanup предшествует repair
и commit; неизвестные внешние эффекты требуют осмотра и reconciliation.
