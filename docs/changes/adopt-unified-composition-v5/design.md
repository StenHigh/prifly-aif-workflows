# Contract and acceptance boundary

The consumer selects declared `/5` points. Each provider owns control anchors,
input bindings, failure routes and consumer keys. A project Step or public Call
returns the exact shared implementation schema to every declared consumer.
Classic/profiled expose verify and review points inside repeat bodies. Fix adds
before-build, before-quality and output-free after-commit. Existing installed
project files and prior Runs retain their original contracts.

```text
consumer point → project/public component → fresh implementation → readers
                         ↓
             original report refs + new assessments
```

The inert native schema closure has frozen 1.0.0 (16 schemas) plus additive
1.2.0 (applicability only). A native package cannot duplicate another trusted
package's schema identity. Explicit installation verifies both locks and every
payload, then imports dependencies first. Compile/prepare never install them.
The builder refuses modified bytes for an already admitted schema identity.
Cross-owner ports use one external exact SchemaRef, not copies of private schemas.

The public `review-for-change` Call accepts original task, implementation and
optional UI/UX configuration. Project measurement can run inside the provider's
exported before-applicability point. Capture follows measurement. A fresh
read-only reader judges task/code/callers; a program guard verifies task digest
and current Git candidate. Wrong/stale evidence becomes a new unknown assessment.
The carrier retains the original report and the new assessment separately.

Required applicability runs existing owned-environment/UI/UX quality only with
valid explicit frontend configuration. Not-required succeeds without browser
Attempts. Unknown and missing required configuration return partial/blocked.
The transport does not decide semantic applicability. Browser unavailability
cannot become a scope exclusion. Standalone UI/UX and low-level exports remain.

Measurement receipts record subject fingerprints, command, selection, runtime,
full logs and actual exits. Readers reuse sufficient applicable receipts. New
commit metadata alone is not a command to repeat all checks. Writers preserve
old refs through repair; subsequent measurements add refs without rewriting old
results. Read-only readers cannot provision or repair an external runtime.

Workflow budgets include the extra Call depth and bounded repeat work while
remaining inside the pinned local policy. They remain finite limits, not a
promise of infinite repair. Root continue uses the current claim holder and
native accepted-prefix semantics; nested resume is not introduced. A minimal
root containing only the acceptance Call does not declare resume. Its attempted
continue correctly refused with resume_prefix_empty; no dummy stage or authority
rewrite bypasses that boundary.

Compatibility evidence separates compilation, scripted transport/routing, actual
browser execution with fresh readers and the owner-selected private pilot.
The private pilot starts from freshly fetched staging and targets Draft MR staging.
Raw private tasks and business details do not enter this public change.
