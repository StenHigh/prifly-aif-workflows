# Проверка собранных версий — issue #17

[Issue #17](https://github.com/StenHigh/prifly-aif-workflows/issues/17) описывает исторический конфликт `aif:step/fix@1.1.0`.
Изменились зависимости шага, а его YAML и авторская версия остались прежними.
Новая проверка выпуска измеряет собранные bytes, включая разрешённые ссылки на инструкции и схемы.

## Проверка выпуска

`tests/compiled_versions.py` собирает предыдущий stable tag и рабочее дерево одним официальным бинарём Pri-Fly.
Обе стороны получают одинаковые stub skills и настройки владельца по умолчанию.
Матрица включает восемь пакетов, три hosts и все объявленные package profiles.
Каждая сторона использует свой `contracts/lock.json` и свои исходники пакетов.
Проверка импортирует только явные зависимости схем в одноразовые authority.

```text
Предыдущий stable tag -> archive -> compile --+
                                            +-> ID + версия + SHA-256 -> отказ при конфликте
Рабочее дерево ------------------> compile --+
```

Проверка сверяет SHA-256 файла с отпечатком, который вернул компилятор.
Агрегированный отпечаток исходников исключает `__pycache__`, `.pyc` и `.pyo`.
Эти служебные файлы Python не входят в исходники компиляции и могут различаться между локальным окружением и CI.
Для step и workflow она также сверяет ID и версию внутри JSON.
Она сравнивает все полученные kind/ID/версии, включая разные варианты матрицы.
Разные отпечатки при одинаковой идентичности дают `compiled_definition_drift` и ненулевой exit code.
Новая итоговая версия допускает изменение bytes.

По умолчанию база — ближайший предыдущий stable tag в истории Git.
На самом release tag проверка выбирает предшествующий выпуск.
Prerelease tags исключены. Отсутствие базы останавливает проверку.
`--baseline vX.Y.Z` задаёт базу явно.
CI получает полную историю Git и сохраняет JSON-отчёт `compiled-version-results`.

## Регрессионные сценарии

Одиннадцать unit tests включают исторические версии из issue.
Отдельные отрицательные случаи меняют только инструкцию или только схему.
Та же версия шага с новым отпечатком должна вызвать отказ.
Другие случаи проверяют новую итоговую версию, повторную сборку и подмену файла.
Пустая выборка не считается успешной проверкой.
Отдельный тест требует неизменного source digest при добавлении Python-кэша и нового digest при изменении YAML.

Native-сценарий использует текущий `aif:step/plan`, который читает owned `task`.
Он сохраняет исходный YAML шага и его авторскую версию `1.7.0`.
Сначала он повторяет одинаковую сборку.
Затем он отдельно меняет текст `aif-plan-bridge` и `task.properties.title.maxLength` с 400 на 401.
Изменение зависимости должно изменить разрешённую ссылку, отпечаток шага и его итоговую версию.
После каждого случая сценарий восстанавливает исходную зависимость.

Это проверка текущего компилятора, а не повторная приёмка исторического Project profile `/2`.
Проверка не запускает Run, не вызывает LLM и не мигрирует уже отозванные пакеты.
Она удаляет собственные временные каталоги и три записи monitor registry.
Границы исполнения `verify` и `compatibility` остаются прежними: компиляция и первый assisted handoff.

## Штатное обновление

README и актуальный release guide теперь требуют `package remove` для вывода старой сборки после завершения зависимых Run.
ID и итоговую версию сборки берут из `package list`.
Если Run удерживает пакет, команда отказывает до разрешения зависимости.
Исходники и owner configuration сохраняют для нужного continue.
`package revoke` остаётся необратимым отзывом доверия, который блокирует прежние pins.
Команда `project workflows remove` отдельно удаляет установленную папку workflow.

Синтаксис и различия проверены по справке официального Pri-Fly `v0.13.90`.
Рабочие authority пользователя не изменялись.
Добавлен [самостоятельный пример](../../../examples/compiled-versions/README.md) с подготовкой Python-окружения и полными командами проверки.
Индекс examples, classic, task-limit guide и root README ссылаются на штатный порядок вывода старой сборки.

## Воспроизведение

`RELEASED_PRIFLY` — абсолютный путь к официальному бинарю Pri-Fly `v0.13.90`.
Для запуска нужен Python 3 с PyYAML; CI устанавливает `PyYAML==6.0.1`.

```sh
python3 -B tests/test_compiled_versions.py
python3 -B tests/compiled_versions.py --binary "$RELEASED_PRIFLY" \
  --report /tmp/aif-compiled-versions.json
python3 -B tests/test_versions.py
python3 -B tests/test_folders.py
python3 -B tools/derive_profiled.py --check
python3 -B tests/verify.py --binary "$RELEASED_PRIFLY"
python3 -B tests/compatibility.py --binary "$RELEASED_PRIFLY"
```
